# v0.2.5：UFI 与屏幕状态同步

本文只记录代码分析与电脑测试，不包含设备标识、口令、短信或账号配置。此次没有访问或修改设备。

## Wi-Fi 状态不一致的原因

原实现通过 datad `wlan.bands[].enabled` 判断 Wi-Fi 开关。对应版本的上游源码表明，该字段表示主 AP 的配置，而 TopFlow 射频关闭还会变更无线设备配置及 AP 接口名称。主 AP 配置仍开启时，屏幕可能错误显示开启，并因等待错误字段变化而提示回读未确认。

改用已有 `wifi.state` 只读操作的 `busy`、`module`、`radios`、`aps` 解释开关和广播状态。该操作虽使用 HTTP POST，但动作语义为读取；不会因为界面刷新调用配置接口。

配置关闭、重载中、已广播、尚未广播及读取未知分别显示。忙碌时不把临时模块卸载解释为用户关闭总开关；数据超过 6 秒不再作为已确认状态。Wi-Fi 配置保存使用后端 `wifi.configure` 的 `result.verified`，广播是否恢复另看最新 `wifi.state`，避免把保存配置与广播完成混为一谈。

## 当前页同步

| 来源 | 页面 / 字段 | 方式 |
| --- | --- | --- |
| datad 实时快照 | 网络、卡状态、速率、散热、流量、终端、频段 | 保留已有数据订阅，检查新鲜度 |
| `wifi.state` | 2.4 GHz / 5 GHz / WPS 可用性 | 当前可见页约每 3 秒，非阻塞 socket |
| 已有原厂、datad、UFI、遨游 getter | 卡源、APN、访客、双频、电源、WPS/SIM 状态、转发概览、策略组 | 当前页约每 5 秒，单个限时只读子进程 |
| 原厂显示配置 | 亮度、自动亮度、休眠时间 | 同一只读任务采样，按现有显示状态安全接纳 |

只读任务有 4 秒上限；每次 UI 循环最多读取 64 KiB，离页、锁定、用户操作和休眠时取消，随后非阻塞回收。锁屏但屏幕亮起时只允许显示策略采样。任务不创建数据文件或新增常驻服务，不输出持续日志。Wi-Fi 独立运输每轮最多读取 8 KiB，超时 2.5 秒。

子进程关闭继承的显示、输入及网络描述符，清除 PIN 输入、表单与 APN 密码。需要短信转发认证时重新锁定会话内存；返回字段只含概览，不包含口令、密钥或完整转发配置。401 撤销父进程失效会话。结果与原页面、卡及策略组绑定，迟到或截断结果不提交。

## 操作保护

- 未编辑 Wi-Fi / 频段 / 显示表单跟随外部修改；编辑中保留本地草稿。
- 确认前核对 Wi-Fi 原配置、APN 稳定 profile ID 及原字段、频段原选择与能力、短信转发原状态。冲突、读失败、取消或重新锁定时不写入。
- Wi-Fi 开关采用绝对目标值；若 UFI 已达到目标，不重复提交。WPS 最终写入前再核对当前 Wi-Fi 状态与操作权限。
- 接口失败显示未知，不主动重试设备写操作。状态读取本身不能触发搜网、发送短信、锁小区或启动配对。
- 外部显示调整不重置休眠计时、不解锁、不唤醒熄灭的屏幕。PIN 或周期唤醒策略发生不受支持的变化时继续按既有安全流程处理。

## 验证边界

回归以真实生产 C 函数配合合成响应、可控时钟、临时文件及运输替身完成；编译目标为 ARM64。测试覆盖面板先关闭、忙碌、模块关闭、读取超时、取消、锁定、同目标去重、草稿冲突、大结果分段、睡眠回收和旧页面结果丢弃。
