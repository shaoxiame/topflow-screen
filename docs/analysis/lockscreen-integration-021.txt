TopFlow 0.2.1 lock-screen integration — local implementation and verification

The SIM-source fix is retained. This increment adds lock-screen telemetry and
bounded visual animation using only the existing sampled device state. No device
connection, write, reboot, installation or live API probe was performed.

Data and display
----------------
lockscreen_status.h consumes the caller's already sampled JSON. Production passes
NULL once the snapshot is older than 5000 ms. There are no network requests in
the new model or view. Mode is aggregation.enabled, the same verified state used
by the home page. Unknown mode remains unconfirmed.

Ordinary mode shows only id=5G card traffic, current operator, actual reported
radio label and connection status. Aggregation mode shows each physical card's
operator and radio label, or its absent/disabled/unknown state, with cellular
traffic summed across the three valid cards. This is explicitly labelled as
three-card cellular traffic; it does not claim tunnel-level effective throughput
and does not add eth0 counters a second time.

external modems. Disabled and absent cards do not contribute cached traffic.

zero. [REDACTED_ENCODED_OR_IDENTIFIER] rates format as an em dash.

Animations and resource bounds
[REDACTED_ENCODED_OR_IDENTIFIER]
Rate changes interpolate between actual samples over 320 ms with quadratic
ease-out, at most one frame every 40 ms (8 update frames). Unknown values and a
[REDACTED_SENSITIVE_CONTEXT]
screens show the current sample directly rather than a sample behind the motion.

Only soft-lock rate rectangles are repainted: two 122x36 clears/text draws and a
256x36 dirty rectangle at (32,222). Full HTML and partial repaint use exactly the
same colors, font weights and normal line height; actual RGB565 framebuffer
comparison verifies identical pixels when the value is unchanged. This catches
both color flashes and one-pixel font-baseline movement between full frames.

The chart uses the existing rate_history.h algorithm: at most 30 actual distinct
timestamped samples per mode, stored separately from home-page history. Ordinary
and aggregation mode have separate scopes; changing mode clears its displayed
history. Stale or unavailable snapshots invalidate the displayed curve. Entering
screen_lock() invalidates the history, numeric motion and shared chart-animation
[REDACTED_SENSITIVE_CONTEXT]
One point remains a waiting state; a curve needs two real samples. No startup
history is generated and missing measurements remain gaps instead of zeroes.

The existing native chart renderer draws white downlink and mint uplink lines
and faint grid/fill in (32,274,256,24), with four bounded interpolation frames
over 180 ms. A growing history interpolates its new endpoint from the preceding
actual endpoint; this is only a drawing transition, never a synthetic sample in
the stored ring. The common chart background cache is reused, not duplicated.
