# v0.2.8：关机、重启回执与快速关机后的持续熄屏

用户反馈：安装上一版后，开启快速开机并关机，插件页面仍然亮着，网络信息变为空值。v0.2.7 修复的是 UFI Shell 命令长度，沿用 v0.2.6 的原生电源处理；它没有解决这次实机反馈。

## 找到的实现缺口

上一版直接读 `/etc/config/zwrt_zte_mc_tmp`，识别 `mode.mode_main_state`，但没有监听原厂独立的 `zwrt_device_power_state_event`。原厂 UI 通过这条事件接收 `mode_power_off`、`mode_power_off_quickening` 和 `mode_power_off_unreal` 等通知，设置本地持续关机标志，并在明确的 `mode_power_on` 后解除。普通休眠/唤醒事件不能替代这条电源事件。

原厂 `libSleep_uci_get` 使用 libuci 默认上下文读取有效状态，包含已保存但未 commit 的变化。因此磁盘文件不是全部运行态的保证。v0.2.8 在接管前使用固定的只读 UCI 查询；运行时直接接收原厂事件，不为每帧启动 UCI 进程。

本次只读访问时，设备已运行原厂 UI，插件目录和进程不存在，LCD 读值为 0，磁盘及有效 UCI 状态均为 `mode_power_on`。这不是照片拍摄时的关机现场，不能据此声称复现或验证了新版本的实际熄屏。未执行安装、屏幕切换或电源动作。

## 修正行为

- 现有 bus helper 增加原厂电源事件监听。事件 OFF 优先于滞后的磁盘 ON；只有明确的 MC ON 才解除事件锁存。同一批先 OFF 后 ON 也会丢弃旧输入和待确认操作。
- 关机期间停止页面数据工作和动画，屏蔽触摸、USB、普通休眠唤醒造成的亮屏，保留原有监管心跳。已开始的亮度事务也会在输出前再次核对电源事件。
- 静默期间每秒只读一次实际背光；若被其他服务点亮，通过原有 LCD 事务重新熄屏，不重复延长插件自己的休眠延时锁。
- 补接原厂 `zwrt_mode_lcd_reboot` 重启通知。普通关机、重启和快速关机的 UI 完成阶段调用 `poweroff_compelte`；只有收到 `mode_power_off_quickening` 才额外调用 `poweroff_quicken_compelte`。两种回执均在实际亮度为 0、原有 LCD 锁已释放且显示事务完成后发送，同一 OFF 周期各至多一次。明确开机使旧回执失效，不自动重试。
- 电源请求保留未发送、部分发送、完整发送、接口已确认的区别，不把中途断线一律当成执行失败。明确长度的完整 HTTP 响应不再等待 EOF；电源请求使用有界 10 秒预算覆盖后端的 8 秒调用期限，收到 OFF 仍立即退出等待处理熄屏与回执。
- 不新增 MC 关机参与者，不调用 subscribe/unsubscribe，不写电源模式、不替代原厂开关机、不增加常驻程序、临时命令文件或持续日志。

具体原厂协议证据见 [原厂电源协议分析](oem-quick-boot-protocol-028.md)及后续补充的[关机与重启回归分析](power-actions-regression-028.md)。后者补全了普通关机回执、重启通知及快速周期双回执，不能把最初的 quickening 单回执方案视为完整方案。完整卸载、恢复原厂与更新机制保留，新增 v0.2.7 精确归档迁移。

## 验证边界

电脑测试覆盖真实事件回调、父子进程协议、OFF/ON 合并、旧状态压制、亮屏中途关机、背光反亮纠正、回执失效与不重复发送；另运行既有显示、锁屏、休眠、状态同步与版本迁移回归。渲染器和 helper 重新交叉编译，成品完整性、隐私及 Shell 命令预算继续检查。

这些检查不替代实机关机、充电、唤醒和触摸验证。用户需替换 UFI TXT 并按新版卡片更新设备组件；只替换面板代码不会升级正在运行的原生程序。最终结果及跳过项见 [公开构建记录](../PUBLIC-BUILD-VERIFICATION.json)。
