四、保留原厂与切换的约束
原厂服务由 procd 管理，设置 respawn [REDACTED_NUMBER]；直接杀进程可能被自动拉起。
原厂进程目前持有 DRM master。同一显示设备的控制权需要明确交接；仅暂停原厂进程并不会自动释放其文件描述符或 DRM master。
/etc/init.d/zte_topsw_devui 的 stop_service 会发送 TERM、KILL，并 rmmod sitronix_ts_spi.ko。因此不能直接把原厂 stop 命令当作安全切换方案。
zte_topsw_daemon.conf 也列出 devui 作为 sync 对象；本地反汇编发现 READY/REG_DONE 同步登记逻辑，没有足够证据把它认定为持续保活。已明确的自动重启来自 procd；停止屏幕后的实际联动仍需验证。
原厂 SDK 初始化存在非查询行为；不应为获取状态在只读调研中执行 SDK 初始化。现有 datad 缓存快照已经提供更合适的数据入口。
未来切换器应保留原厂二进制、资源、启动配置；只在明确授权的实机阶段处理显示服务、控制权、输入与退出回退。不得顺带停止联网或系统守护服务。
退出自定义界面后，需验证原厂显示、触摸、亮灭屏、休眠唤醒、联网与异常退出恢复；这些测试本次均未执行。
静态分析细节见 display-binary-analysis.txt。
