结论边界
当前结论：不能发布为“已无损适配原厂功能”。原厂 UI 本身提供 zwrt_deviceui 服务，并承担部分亮度/休眠/风扇策略；停止 UI 可能让这些服务及策略消失，这是实质性兼容阻塞，不是截图测试能消除的限制。独立供电已有 zwrt_bsp.charger 接口可用，但不等于全部 UI 托管职责已经补齐。参见 lifecycle-readiness.txt。
其余接口设计有现成依据，安装/停止/恢复/组件清理的代码边界明确；不能据此声称已经实机无损运行或恢复成功。DRM 接管、原厂进程恢复后的真正画面和触摸、功耗/内存占用必须在用户认可 UI 且明确允许安装后实测。本地截图证明的是同一 litehtml/FreeType 排版，不证明 DRM 驱动或触摸方向。

一、只读证据支持的事项
1. [REDACTED_ENCODED_OR_IDENTIFIER].init：原厂程序 [REDACTED_ENCODED_OR_IDENTIFIER] 受 procd 管理，设 respawn。其 stop_service 除 killall 外还执行 rmmod sitronix_ts_spi.ko。因此不能通过 vendor stop/restart 直接切屏，否则可能卸载触摸。
2. 当前 supervisor 仅 ubus service delete 指定 zte_topsw_devui，随后等确切原厂 exe 消失再启动插件；不调用 vendor stop/restart、不 rmmod。恢复仅 init start。该方案避免执行已知危险 stop hook；具体固件 procd 删除是否确实抑制 respawn 以及其他守护程序是否重启显示，尚需实机确认。已有 ubus-schema-explicit.txt 实际返回 Not found，不能把它当成功 schema 证据。
3. drm-state.txt：card0、msm_qpic、DIN-1、320×480、RGB565、pitch640，原厂进程是 DRM master。插件枚举当前 connector/crtc、检查尺寸，关闭时释放本身 DRM fd。未替换原厂程序/库/init 文件。
4. display.txt：sitronix 触摸为 evdev；当前 touch_input.c 只 O_RDONLY|NONBLOCK 打开符合 ABS 能力的设备，无 EVIOCGRAB，无卸载驱动。它选第一个符合条件的触摸设备，实际坐标/旋转/多触点行为仍需现场验证；不应写“触摸已验证”。
5. zte_topsw_daemon 为独立 procd 服务。当前切换脚本不停止该 daemon，也不停止 UFI、datad、Mihomo、网络或聚合服务。切屏程序会持有 DRM、读取 evdev，电源键逻辑会写现有 led:lcd brightness；因此运行后并非设备全局“零写入”，这是显示职责所需的变化。开发取证阶段仍然零设备写入。
