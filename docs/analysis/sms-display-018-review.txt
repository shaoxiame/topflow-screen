Display and lock
The old settings page required a fully ready light sensor before showing all
settings. A transient disabled/unreadable sensor could hide the page, including
its lock entry. Settings now read persistent policy independently; the lock
entry is always at the page top, and failures show a bounded diagnostic code.
Strict adoption/preflight checks are retained. Manual brightness and timeout
remain usable when lux is temporarily unavailable.

The old wake path rendered but only read lux, whereas startup separately
prepared the light sensor. Factory sleep can leave sensor enable at zero.
The wake path now reuses guarded sensor preparation after a complete frame,
[REDACTED_SENSITIVE_CONTEXT]
the same only when the panel is actually on. Fixed mode needs no sensor I/O.

Enabling automatic brightness from fixed mode prepares a real sensor sample
only after confirmation. A temporary owned frame guard is released via the
existing same-level display transaction. Pending sleep/resync, cancellation,
policy change, missing sensor identity, missing lux, or expired guard prevents
the configuration commit. A failed commit does not change the fixed preference
in the local model. Sensor preparation can transiently enable the sensor even
if the subsequent commit fails; it never forces LCD off/on or overwrites the
previous fixed brightness preference.

Parent integration separates factory power event 1 (sleep) from 2 (wake).
Repeated wake while already awake performs no relock or output transaction.
