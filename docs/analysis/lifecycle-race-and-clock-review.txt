- supervisor rejects malformed, backward and future heartbeat samples and

Lifecycle:
- installer creates .lifecycle.lock once inside its newly owned directory.
- start/restore/uninstall open that EXISTING anchor read-only before creating
  RUN. They never recreate a deleted lock. Extraction/finish uses the same
  installation lock, then the existing runtime control lock (7 before9).
- after lock acquisition they compare held descriptor inode with current path,
  installation directory inode and ownership marker. Same-path replacement,
  even with byte-identical package ownership, cannot pass the old lock.
- /proc/self/fd/7 is deliberate: memoryController runs in a POSIX subshell,
  where $$ still names the outer shell. stat inherits the actual descriptor.
- startup inherits7 to supervisor; child verifies same anchor and re-flocks
  the inherited open description. It publishes lifetime identity while8 held,
  then closes7. The launching controller keeps7 until it observes publication.
- restore/uninstall can subsequently take7 and cancel the supervisor, waiting
  for8 to be released after complete cleanup. Original startup receives no
  plugin lock descriptors. Uninstall removes executable entries first and
  the lifecycle anchor last, while still holding its open descriptor.
