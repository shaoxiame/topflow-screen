# v0.2.7：UFI Shell 命令长度修复

用户在导入 v0.2.6 后看到“UFI Shell 调用失败：返回值或执行结果未确认”，不能读取屏幕最新状态。

## 根因与只读复现

v0.2.5 的完整状态命令为 123,572 字节；v0.2.6 加入上一版的精确迁移清单后增长到 141,536 字节。每个历史文件的类型、链接数与 SHA 校验都展开成一段重复 Shell，加上内联恢复控制器，超过了 `sh -c` 的单参数长度边界。UFI 的 HTTP 请求本身可以返回 200，但 Shell 没有成功执行，响应为 `success:false` 且 `content` 为空。

本次通过当前 UFI 的既有接口做了只读复现：39 字节的固定 `printf` 命令成功；在同一个命令前加入纯注释、使总长变为 141,536 字节后，返回上述空失败结果。探针没有读写设备文件、改变设置、停止服务或安装组件，凭证只保存在本次电脑进程内存中。公开记录不包含身份口令或设备标识。

这不是登录密码校验失败，也不表示原生屏幕程序已经损坏；不能通过放宽 `success` 检查把失败当作成功。

## 修复

历史文件校验提取为共享 Shell 函数，精确文件清单、SHA、链接检查、受控清理状态和生命周期锁内再次核验继续保留。只允许当前安装版本执行的壁纸操作不再展开最终必然拒绝的历史版本分支。没有加入压缩工具依赖，没有在设备落盘保存命令。

发送前按 UTF-8 字节计数，超过预算时在浏览器直接拒绝，不请求 UFI、不自动重试。构建回归使用真实完整载荷和完整尺寸的壁纸分块，防止短测试样本掩盖长度问题。

v0.2.7 沿用 v0.2.6 的原生屏幕程序，包含快速开机假关机联动及 UFI 首页透明卡片修复。本次只调整管理命令生成和长度保护；版本更新与原生归档清单重新生成。v0.2.6 原始 TXT 和源码历史保留，不覆盖已发布字节。

修复后的状态命令为 **88,266 字节**，完整操作中最长的壁纸迁移分块命令为 **91,913 字节**。将修复后的完整状态命令通过同一 UFI 接口只读执行，返回 HTTP 200、`success:true` 及有效的 `TOPFLOW_SCREEN` 状态标记；未执行安装或屏幕切换。见 [长度探针](ufi-shell-size-readonly-027.json) 与 [实际状态读取](ufi-status-readonly-027.json)。

## 验证边界

迁移、锁屏壁纸、卸载、命令预算与导入兼容测试在电脑执行；UFI 仅做只读接口核对。本次没有代用户安装 v0.2.7，也没有把只读接口结果当作屏幕触摸、关机或休眠的实机验收。最终测试结果见 [公开构建记录](../PUBLIC-BUILD-VERIFICATION.json)。
