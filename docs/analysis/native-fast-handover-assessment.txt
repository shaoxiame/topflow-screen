Conclusion
The current evidence does not establish a safe instantaneous handover through
an existing public original API. This is an evidence limitation, not a claim
that an alternative can never be engineered. Do not skip the waiting checks or
delete the original locks based only on their names. The displayed remaining
317 seconds is the remainder of the 360-second deadline, not a required delay:
the current implementation continues as soon as both original locks clear.

Conditions needed for an independently designed faster protocol
- Prove exclusive producer/ownership of each original lock, including any
  other SDK users and already queued messages, while preventing respawn.
- Provide a confirmed, atomic or otherwise race-audited transfer/release
  operation; a stable truncate-written map plus PID disappearance is not CAS.
- Obtain/track the original timer's true remaining interval, or explicitly
  accept and document a changed policy. Starting a fresh180s lease when the
  original has already been dark for120s delays sleep by an extra120s and
  cannot be described as preserving its remaining timer.
