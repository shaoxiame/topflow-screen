Architecture
Independent AArch64 static litehtml/FreeType renderer for the original 320x480
RGB565 DRM screen, original device font, rotated evdev input, five horizontal
swipe pages, vertical scrolling subpages, light/dark themes, finite swipe
transitions, bounded busy feedback, real RAM-only rate history. It is not a
browser: no JavaScript DOM is executed on the device. Native templates and C
routes share the visible design of the separate browser preview.

The current native main pages follow the existing browser layout at 320x480.
Large rate values, labels and card status use the same presentation rules;
1000.0+ Mbps values reduce font size without removing their units. CSS font
weight now affects both measured width and raster coverage. Native RGB565
gradients use fixed ordered dithering, with no temporal noise or extra redraw.
The blue hero contains actual download/upload lines and subtle area shading.
Two independent histories retain at most 30 primary/aggregate samples in RAM;
missing samples form gaps, never zeros. New samples can interpolate over four
45ms frames; idle data never starts an animation loop. No preview fixture or
chart file is loaded by the ARM runtime. The upstream forced-HSR environment/
temporary-file debug override has also been removed from the data backend.

The helper dynamically links only the existing musl/libubus/libubox ABI. It uses
a private socketpair, observed original service methods and LCD/LOGIN/TOUCH and
sleep/wake contracts. It does not load or initialize the original closed SDK.

A second legitimate handover condition is now handled explicitly. The original
display owns an internal zte_topsw_devui map entry while active. Its SDK deletes
that entry when ready for sleep. The separate kernel
[REDACTED_ENCODED_OR_IDENTIFIER] is released by an original-process timer 180000ms
after the screen turns off; lighting the screen pauses that timer and acquires
the lock. Stopping the original before that timer fires could strand its lock.
The correction waits for both locks to disappear naturally while the original
continues to run. It never deletes a vendor lock or changes the screen timeout.
The controller provides bounded waiting and specific diagnostic codes; a known
always-on configuration with the internal lock active refuses immediately.

The map writer truncates then rewrites its full tree on add/delete. Therefore a
zero-length or incomplete read is not proof of no lock. Native reads now require
a nonempty newline-complete map, unchanged inode/size/mtime/ctime before and
after each read, and two identical snapshots 100ms apart. Unknown syntax/read
errors refuse; transient incomplete/changing snapshots are reported separately.
After the original stops, both the stable map and exact kernel lock are checked
again before any replacement provider registration or DRM operation. A race
returns to original recovery rather than clearing the original lock.
